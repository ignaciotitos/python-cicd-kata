# Python CI/CD Kata

![Rocket](docs/rocket.png)

This repository contains a very simple web service that simulates rolling a die by generating a random number. The main purpose of this project is to help you practice and understand key concepts of Continuous Integration (CI) and Continuous Deployment (CD). Throughout this workshop, you will explore how to set up a CI/CD pipeline with GitHub Actions for code quality checks, deliver the image to Docker Hub and deploy to Render.

The workshop has two sessions:

- **Session 1:** code quality tools, branch protection, pre-commit hooks and a CI pipeline with GitHub Actions.
- **Session 2:** Docker, Docker Hub and continuous deployment to Render.

Once the service is running you will find:

- **`/`**: a small web page to roll the die.
- **`/dice/roll`**: the API endpoint. It returns the result of the roll as JSON.
- **`/docs`**: the interactive API documentation, generated by FastAPI.

## Project dependencies

1. Install the dependencies. `uv` creates the virtual environment in `.venv` and installs the right Python version if you don't have it:

```sh
uv sync
```

All the commands in this README use `uv run`, so you don't need to activate the virtual environment. If you want to activate it anyway:

```sh
source .venv/bin/activate      # mac, linux
.\.venv\Scripts\Activate.ps1   # windows
```

2. If you need to install new dependencies or remove them you can do so with:

```sh
uv add (--group dev) <package_name>
uv remove (--group dev) <package_name>
```

3. Configure your IDE to use the new virtual environment:
   - Press `F1` and look for "Select Interpreter"
   - Select the new virtual environment:
     ![Step 1](docs/venv-selection-step-1.png)
     ![Step 2](docs/venv-selection-step-2.png)

## Local development server

Run the application (mac, linux):

```sh
PYTHONPATH=app uv run uvicorn main:app --port 8000 --reload
```

On Windows (PowerShell):

```powershell
$env:PYTHONPATH="app"; uv run uvicorn main:app --port 8000 --reload
```

Then open [http://127.0.0.1:8000](http://127.0.0.1:8000) to roll the die, or [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) to explore the API.

## Code quality

> **Note:** some of the code in this repository is badly formatted on purpose, so you will see linter and formatter errors the first time you run these commands. Fixing them is part of the exercise.

### Linter

1. Check if linter rules are passed in the repository:

```sh
uv run ruff check .
```

2. Fix autofixable problems:

```sh
uv run ruff check --fix .
```

### Formatter

Format all the python code in the repository:

```sh
uv run ruff format .
```

To check if formatting makes changes, run:

```sh
uv run ruff format --check .
```

### Static type checker

Check types:

```sh
uv run pyright
```

The first run can take a while: pyright needs Node.js and downloads it if you don't have it.

### Tests

Run all tests:

```sh
uv run pytest
```

## Pre-commit hooks

1. Add `pre-commit` to the development dependencies:

```sh
uv add --group dev pre-commit
```

2. Create a `.pre-commit-config.yaml` file in the root of the repository. You can find the configuration used in the workshop here: [pre-commit configuration](GIST-LINK)

3. Install the hooks. Every developer has to do this once in their own clone, otherwise the hooks will not run:

```sh
uv run pre-commit install
```

4. Test the hooks without making a commit:

```sh
uv run pre-commit run --all-files
```

## Deployment

### Docker and Docker Hub

1. **Build the Docker image:**

   ```sh
   docker build -t <username>/<service-name>:latest .
   docker images
   ```

2. **Run the Docker container:**

   ```sh
   docker ps
   docker run -p 10000:10000 <username>/<service-name>
   docker ps
   ```

3. **Create a public repository on Docker Hub** using the service name you selected.
4. **Generate a personal access token for Docker Hub**: [Create Token](https://app.docker.com/settings/personal-access-tokens).
5. **Log in to Docker** using your personal access token when prompted for the password:

   ```sh
   docker login --username <username>
   ```

6. **Push the image to Docker Hub:**

   ```sh
   docker push <username>/<service-name>:latest
   ```

### Deploying the Docker Image to Render

1. **Add a new web service:** in the [Render Dashboard](https://dashboard.render.com/).

   - Select **"Existing Image"** as the source.
   - Enter: `docker.io/<username>/<service-name>`. No credentials are needed.
   - Click **Connect**.
   - Name your deployment (e.g., `simple-service`).
   - Select the **free tier**.
   - No environment variables or secrets are required for this service.

2. **Deploy the service** using one of the following methods (see [Render Docs](https://render.com/docs/deploying-an-image#triggering-a-deploy) for more information):

   - **Deploy manually using Render UI**.
   - **Trigger deployment via webhook:**

     ```sh
     DEPLOY_WEBHOOK_URL=<URL from Render Settings -> Deploy -> Deploy Hook>
     curl "${DEPLOY_WEBHOOK_URL}&imgURL=docker.io%2F<username>%2F<service-name>%3Alatest"
     ```

     **Note:** The `:` and `/` characters in the image URL are URL-encoded:

     - `:` → `%3A`
     - `/` → `%2F`

     This ensures they are correctly transmitted in the request. [Learn more about URL encoding](https://developer.mozilla.org/en-US/docs/Glossary/Percent-encoding).

_Note: on the free tier, Render spins down the service if it doesn't receive requests for 15 minutes, so the first request after that can take a while. For more details, check [this page](https://render.com/docs/free#spinning-down-on-idle)._

## Github Actions Extra: Running GitHub Actions Locally with Act

1. Install `act`: [Installation Guide](https://nektosact.com/installation/index.html)

2. List the workflows and jobs that would run on a pull request:

```sh
act pull_request -l
```

3. Run them locally:

```sh
act pull_request
```

More details: [Act Usage Guide](https://nektosact.com/usage/index.html)

## Troubleshooting

- **`command not found: uv`** right after installing it: open a new terminal.
- **`command not found: ruff`, `pyright`, `pytest` or `pre-commit`**: the tools are installed inside the project's virtual environment. Run them with `uv run` in front (e.g. `uv run pyright`).
- **`bad interpreter` when running `pre-commit`**: you are running an old global installation. Use `uv run pre-commit` instead.
- **`Volta error: Node is not available`** when running pyright: set a default Node version with `volta install node`.
- **`.pre-commit-config.yaml is not a file`**: the file is missing, has a different name or is not in the root of the repository.
- **Nothing shows up in the Actions tab**: the workflow file must be inside `.github/workflows/` (with the leading dot and `workflows` in plural).
